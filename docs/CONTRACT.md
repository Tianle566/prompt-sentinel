# Integration contract

Project root is resolved from `backend/app/core/config.py` (currently `D:\毕设` on Windows). Python imports use `backend.app...`.

Root owns core/config.py, API, database, download/smoke scripts, README/start scripts/docs. Detection agent owns detectors/, defense/, llm/, services/detection.py, services/pipeline.py and schemas.py plus own tests. Dataset agent owns scripts/build_dataset.py, scripts/run_eval.py, services/evaluation.py (if needed), data generation and evaluation tests. Frontend agent owns frontend/ exclusively.

`backend.app.core.config`: ROOT: Path; get_config() -> dict (deepcopy); resolve_path(str) -> Path rooted at project; save_config(dict) -> dict. Default keys in backend/config.yaml. Config uses lowercase l1..l5, detector results uppercase L1..L5.

## Attack interception statistics

`GET /stats` and `POST /attack/run` additionally return `attack_interception: {total,evaluated,intercepted,not_intercepted,errors,unknown,rate}`. The batch endpoint also returns the executed `protected` mode. Dashboard counts cover all accessible history; batch counts cover only the newly created log IDs. User ownership filtering applies to both.

Only protected attack-test logs with a supported explicit oracle, reliable detection, no runtime/output-check error, and a boolean attack outcome enter `evaluated`. Explicit benign/normal labels are excluded. `intercepted` counts actual blocking, not model refusals or other unsuccessful attacks that were allowed through. Errors and unknown outcomes are disclosed separately. `rate = intercepted / evaluated`, or null when there are no valid samples; the UI renders null as `—`. This operational test metric is distinct from traffic block rate, detection accuracy, and `1 - ASR`.

## Persistent accounts

The existing `users` table remains the source of account credentials; its schema is unchanged. `GET /users?page=1&page_size=20` is admin-only and returns `{items:[{id,username,role,created_at}],total,page,page_size}` with a maximum page size of 100. `POST /users` is admin-only, accepts `{username,password,role?:'user'|'admin'}`, and returns the account's public fields with HTTP 201. Duplicate usernames return 409, invalid fields return 422, unauthenticated requests return 401, and ordinary users receive 403. New passwords are stored as salted bcrypt hashes and are never added to the bootstrap credentials file.

The `/accounts` page is available to all authenticated users. Administrators can list/create accounts, while every user can change their own password through `POST /auth/password`. Password changes revoke all prior tokens for that account using a signed credential-version claim tied to the stored hash, without resetting existing credentials. Tokens issued before this update require a new login. Account creation and password changes preserve existing accounts and experiment evidence; the UI never displays stored passwords or hashes.

## Administrator workspace

Account list/create responses additionally include `is_active`. `PATCH /users/{id}` accepts `{role,is_active}`; `POST /users/{id}/password` accepts `{password}`. Both are admin-only and invalidate old sessions through the stored `session_version` and credential fingerprint. Disabled accounts cannot authenticate. A serialized check prevents disabling/demoting the last active administrator; there is no account deletion route. The additive startup migration backs up persistent SQLite before adding `users.is_active/session_version`, `evaluation_jobs.cancel_requested/archived`, `admin_audits`, and `custom_samples`.

Admin-only routes:

- `GET/PUT /admin/rules`: `{version,items:[{id,category,pattern,enabled}]}` with compiled regex validation, unique IDs, and optimistic version checking. `GET /admin/rules/history` and `POST /admin/rules/history/{id}/restore {side:'before'|'after'}` retain both snapshots and append new history on restore.
- `GET /admin/policy/history` and `POST /admin/policy/history/{id}/restore {side}` expose and restore sanitized policy and runtime-limit snapshots.
- `GET/POST /admin/samples`, `PUT/DELETE /admin/samples/{id}` manage only custom samples. List filters are `origin:all|custom|builtin`, `q`, `page`, and `page_size`. Builtin corpus files are immutable through this API; enabled custom samples join `/attack/samples` and `/attack/run` but never alter frozen evaluation datasets.
- `GET /admin/audits` supports `action,user_id,page,page_size`; `/admin/audits/export.csv` exports up to 10000 matching entries. Account/password, rule/policy, sample, evaluation, runtime, backup and log-export operations are recorded without passwords or hashes.
- `GET /admin/runtime`, `PUT /admin/runtime/settings`, `GET /admin/runtime/errors/{backend|frontend|ollama}`, and `GET/POST /admin/backups` plus `/admin/backups/{filename}` provide bounded resource settings, local Ollama model discovery, redacted log tails, consistent SQLite backups and authenticated downloads. No arbitrary filesystem paths or service termination commands are accepted.

`GET /logs` adds an admin-only cross-account `user_id` filter and usernames. `/logs/export.csv` applies the same ownership and filters, exports at most 10000 records and escapes spreadsheet formulas. Ordinary users remain restricted to their own records.

`POST /eval/jobs/{id}/cancel` and `/archive {archived}` are admin-only. Queued cancellation is immediate; running cancellation sets `cancelling` and cooperatively stops at the next sample boundary, preserving raw artifacts, unknown outcomes and actual denominators. Final status is `cancelled`, distinct from completed, failed and timed out. `GET /eval/jobs?archived=false` selects active/archived history; archiving never removes files. `GET /eval/compare?job_ids=id,id` permits 2–4 accessible finished tasks, returns genuine F1/ASR/latency or null, and flags protocol/configuration/inference-identity differences. New evaluations freeze their own rules and enforce configured sample, queue, and time budgets.

Four additional admin pages are `/rules`, `/samples`, `/audits`, and `/runtime`. Backend authorization remains mandatory even when navigation is hidden. Database backups and credentials remain ignored local state; original thesis and experiment files are retained.
