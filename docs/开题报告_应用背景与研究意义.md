# 开题报告：应用背景与研究意义

论文题目：面向大语言模型应用的提示词注入攻击检测与多层防护系统设计与实现

具体应用定位：企业办公资料的本地文档摘要与对话助手。以下为拟定、模拟的研究场景，不表述为已经落地的企业项目；不扩展为尚未实现的知识库检索或自动执行工具系统。

## 一、应用背景

随着大语言模型文本理解与生成能力的发展，智能办公应用已经将自然语言交互与文档阅读相结合，用于长文摘要、信息归纳和辅助写作。以 Microsoft Copilot in Word 为例，其官方教程已经提供文档摘要、关键要点提炼等功能，表明大语言模型处理办公资料具有明确的产品应用基础。此类应用的价值不仅在于生成文字，还在于帮助使用者在阅读较长材料时定位主要内容，为后续人工核对和处理提供辅助。[1：微软官方文档摘要教程](https://support.microsoft.com/en-gb/word/copilot/create-a-summary-of-your-document-with-copilot-in-word?nochrome=true)

本课题拟将企业员工的办公资料阅读作为具体应用场景。员工需要对会议纪要、项目说明、管理制度以及供应商提供的技术资料进行归纳，可通过普通对话提出问题，或将相关材料导出为文本文件上传，获得内容摘要。系统管理员负责维护防护策略、查看异常输入及处理记录。该场景具有清晰的业务链路：用户提交问题或文档，应用构造提示词并调用模型，模型生成结果后再展示给用户，因而适合开展提示词注入风险分析与防护验证。

在上述流程中，开发者设定的系统指令、用户提出的业务要求和文档正文分别承担不同作用，其来源与可信程度也不相同。外部材料应当作为待分析的数据，而不应自动获得修改系统任务的权限。然而，模型需要同时理解这些自然语言内容，攻击者便可能利用其中的指令性表述诱导模型改变行为。Greshake 等人的研究表明，攻击者不必直接与应用对话，也可以通过应用随后读取的外部数据实施间接提示注入，使数据来源与任务指令之间的边界受到破坏。[2：间接提示注入原始研究](https://arxiv.org/abs/2302.12173)

从攻击入口看，普通对话中的恶意要求可以形成直接提示注入；合法用户上传的材料中夹带操纵性文字，则可能形成间接提示注入。例如，员工原本希望概括项目会议纪要，但文档中的恶意附注却要求助手放弃摘要、返回预设结论或披露内部指令。此时，用户的操作本身可能完全正常，风险来自被处理材料。NIST 的对抗机器学习分类报告将间接提示注入与外部资源控制联系起来，并指出其可能影响系统的完整性、可用性与隐私。[3：NIST AI 100-2e2025](https://doi.org/10.6028/NIST.AI.100-2e2025)

这类风险已有实际产品漏洞作为研究依据。2025 年公开披露的 EchoLeak 涉及 Microsoft 365 Copilot：发现团队通过概念验证展示了不可信邮件内容可能引发的信息泄露风险，微软将其登记为 CVE-2025-32711，并确认问题已完成缓解。发现者披露也说明没有客户受到影响。该案例揭示的是已验证漏洞的风险，而非客户数据泄露事故，也说明内部使用权限不能替代对外部内容的信任边界管理。[4：微软官方漏洞公告](https://msrc.microsoft.com/csaf/advisories/2025/msrc_cve-2025-32711.json)、[5：发现团队披露](https://www.catonetworks.com/blog/breaking-down-echoleak/)

在安全治理方面，OWASP 将提示词注入列为《2025 年大语言模型应用十大风险》的 LLM01，并明确指出检索增强生成等技术并不能完全消除该风险。[6：OWASP LLM01:2025](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) 对本课题拟定的办公场景而言，防护还需要兼顾正常使用：企业制度和操作说明本就包含指令性语言，简单禁止某些词语容易影响合法摘要任务；仅要求模型忽略恶意内容，也需要通过实验检验其可靠性。微软公开的防护方案采用提示加固、不可信内容隔离、攻击检测与影响缓解相结合的纵深防御思路，为应用层研究提供了工程参考。[7：微软纵深防御说明](https://www.microsoft.com/en-us/msrc/blog/2025/07/how-microsoft-defends-against-indirect-prompt-injection-attacks)

基于此，本课题拟围绕普通对话和上传文档摘要两个入口，构建本地可运行的提示词注入检测与多层防护原型。系统结合规则过滤、预训练分类模型、多语言安全审核、提示加固和输出检查，记录各层判断及耗时，并通过对照与消融实验分析不同策略的效果和代价。研究使用公开数据和明确标注的本地构造样本，以随机测试秘密模拟泄露目标，不接入真实企业机密资料，也不向第三方服务开展攻击测试。

## 二、研究意义

本课题的研究意义首先体现在对应用信任边界的分析。通过区分系统指令、用户请求和文档正文，可以将“模型是否生成了某种内容”进一步转化为“模型是否遵守原始任务、是否将不可信数据误当作控制指令”等可验证问题。这有助于避免将普通文档中的操作说明一概视为攻击，也避免把一般内容安全风险与提示词注入完全等同，使攻击分类、样本标注和结果解释更加清晰。

其次，本课题能够提供多层防护策略的实证比较。规则、分类模型、安全审核、提示构造和输出核查分别作用于不同环节，其组合效果不能仅凭功能数量判断。通过分别设置无防护、单类防护、完整防护与逐层移除等条件，并同时考察精确率、召回率、误报率、攻击成功率和推理延迟，可以分析各层是否互补，以及防护收益与正常任务可用性之间的关系，而不预设层数越多效果就必然越好。

最后，本课题具有工程实践与教学验证价值。以本地预训练模型为基础，结合权限控制、可配置策略、段落风险展示和日志审计，可以形成覆盖输入、处理与输出的完整实验原型，为同类文本处理应用提供可复现的设计参考。针对拟定场景中的中文办公材料和英文技术资料分别评估，也有助于识别不同语言条件下的适用边界。研究目标是在限定场景中验证防护效果及其局限，不承诺彻底消除提示注入风险，不将合成测试秘密的泄露率直接等同于真实企业机密的泄露概率。
